## 一、你的直觉是对的，而且比你想的更值钱

「红衣会爆肚兜，然后当衣服穿，增加吸血或自动回血」——这个设计的价值在于：

> **8 张反派立绘是已经完成、已经预缓存、但代码里零引用的美术资产。**
> 装备系统可以让它们**变成机制**，而不仅是图。

现有代码里 `assets/portrait/villain-*.jpg` 那 6 张死资源（见主审计 P0-3），**每一张都对应一个传说妖**。让它们掉落专属装备，死资源就变成了内容。

## 二、现状实测

| 项 | 现状 |
|---|---|
| 装备系统 | **全仓 0 处** |
| 词条 / affix | **全仓 0 处** |
| 宝石 | 有，但 `director.js:16` 的**刷怪燃料**，不是装备宝石 |
| 传说妖掉落 | **8 只在砍杀局里 0 掉落** |
| 词条骨架 | ✅ **`upgrades.js` 的 12 个 PASSIVE**（name/icon/maxLv/desc/mode 全套） |
| 属性系统 | ✅ `player.stats` 12 个属性 + `shieldMax` + `addShieldCapacity()` |

**结论：不用从零设计。** `upgrades.js` 就是一套现成词条系统，`equipment.js` 沿用了同一套 schema。

## 三、四个槽位（少而精）

```
兵刃  weapon   你的手。
衣袍  robe     贴着皮的那层。
法器  relic    借来的力。
符佩  charm    挂在腰上的。
```

**为什么只设 4 个**：现有 4 角色 × 12 词条已经是 48 个组合。再乘槽位数，「每局穿什么」会变成排列组合题而不是一个决定。**6 槽以上就该砍。**

## 四、17 条词条，分 4 档

### T1 常见（3 条）—— 白给就拿
| 词条 | 效果 |
|---|---|
| 锋锐 | 攻击 +8%/层 |
| 轻身 | 身法 +6%/层 |
| 坚韧 | 护甲 +1/层 |

### T2 精良（7 条）
疾息（冷却 -6%）、厚生（生命 +15）、引灵（拾取 +20%）、积财（金币 +12%）、悟道（经验 +10%）、**自愈**（6s 回 1.5%）、**魁伟**（范围 +12% 且冷却 -4%）

### T3 珍奇（5 条）
阔野（范围 +8%）、锐目（暴击 +4%）、**饮血**（伤害 3% 转治疗）、**玄甲**（护盾 +10 且加速回复）、**反震**（受伤 5% 弹给近敌）

### T4 传说（2 条）
**通玄**：随机一门神通 +1 级（局内）
**化形**：随机改变一门神通的**形态表现**

> 你说的「给技能多一级」「多一个护盾」「体型大小」「技能样式变化」——**全在这 17 条里**，而且是 T3/T4 档，不是人人都拿得到。

## 五、8 只传说妖的招牌掉落

**每件装备的机制都能从这只妖的设定里读出来。** 不是「红衣给的护甲 +10」，而是「她穿着嫁衣等了很多年 → 那件衣服会替你愈合」。

| 传说妖 | 掉落 | 槽位 | 机制 | 风味文案 |
|---|---|---|---|---|
| **红衣女鬼** | **红嫁衣** | 衣袍 | **自愈 4.5%/6s** | 「针脚很拙。她本来不用会这个。」 |
| 黑山姥姥 | 碎愿牌 | 符佩 | 吸血 9% | 「字丑是因为她不识字。」 |
| 白泽 | 白泽之问 | 法器 | 神通 +1 级 | 「它不评判答案。它只记着。」 |
| 当康 | 当康角 | 兵刃 | 范围 +26% | 「它不是跑，它是领路。」 |
| 青穹 | 青穹之翼 | 兵刃 | 暴击 +22% | 「它说了三个字：『因为你。』」 |
| 剑骨 | 第三百零一柄 | 兵刃 | 攻击 +47%、形态变 | 「多出来的那一柄，没有主人的名字。」 |
| 墓前石将 | 半句碑文 | 法器 | 护盾 +40 | 「此生不悔，奈何无人共。」 |
| 灯尸 | 引路灯 | 符佩 | 反震 15%、自愈 4.5% | 「灯不回头。」 |

**红衣爆红嫁衣给你自愈** —— 就是你说的那个设计。实测通过。

**重要设计约束**：这 8 件**不在砍杀局的普通掉落池里**，只能通过修仙阁支线/副本结算获得。**所以拿到就是拿到了，不会被刷爆。** 这也让「搜打撤」有了明确的终极目标。

## 六、工匠挂在地图上

```
铁匠 老周  @n9 落云镇   强化
绣娘 阿禾  @n0 青石村   重铸 / 外观
琢玉人    @n4 青岚秘境  宝石镶嵌
```

**「去地图找工匠」这个需求不需要新的节点类型** —— 沿用 `nodes.js` 的 facet 思路，工匠是节点的**一个身份**，不是一个类型。

**强化不降级**，只涨不跌（降级会把玩家气走）。

实测：`+3 → +5` 花费 54 源石。

---

## 七、宝石（只 2 个槽）

宝石**只在「法器」和「符佩」上开槽**，每件 1 个。

> 理由：4 槽都镶 = 4 条额外词条，数值直接翻倍。限制在 2 槽是平衡。

赤玉（攻击+6%）、碧玉（生命+20）、玄玉（护盾+6）、素玉（冷却-5%）、白纹玉（暴击+3%）

实测：法器只有 1 槽，镶第二颗返回「槽位已满」。

## 八、外观（纯装饰）

```js
cos_hongyi: { name:'红嫁衣', slot:'robe', note:'见阿禾' }
cos_qingqiong: { name:'青翎', slot:'weapon', note:'回头那次的' }
```

**属性全为 0，只换贴图。**

存在的理由：搜打撤的「带出来」如果没有「带出来的是什么」会很空。**玩家会想把那件红嫁衣穿出去。** 这也是解锁外观的动机。

## 九、数值平衡：一个必须处理的隐患

实测发现：4 件 T4 + 12 局内被动满级，`might` 会到 **2.9**，而敌人 HP 曲线跟不上。

**解决**：给装备乘区加一个总系数衰减。

```js
const GEAR_POWER = 0.7;
for (const k of Object.keys(mul)) mul[k] = Math.pow(mul[k], GEAR_POWER);
```

**实测效果**：
```
两件兵刃后 might:        1.31
再叠 5 级「锋锐」:       1.92
原版（无装备）12 满级:   1.47
→ 装备 + 词条 = 1.92，比原版高 31%
```

**31% 是合理的「有装备就该更强」，且不会到 2.9 的失控区间。** `GEAR_POWER = 0.7` 需要后续实测调。

## 十、与现有系统的接点

| 要改什么 | 位置 | 注意 |
|---|---|---|
| 词条 schema | 沿用 `upgrades.js` 的 PASSIVE | 不要另起一套 |
| 属性写入 | `applyGear()` 键名对齐 `player.stats` | 无需映射表 |
| 护盾 | `player.addShieldCapacity()` 现成 | `player.js:119` |
| 吸血/自愈 | 在 `enemies.js` 伤害结算处读 `p.lifestealRatio` | **需要加这一处** |
| 反震 | 已有 `p.reflectRatio` | `upgrades.js` 的反震诀已在用 |
| 神通 +1 | `p.pendingArtBonus`，接 `upgrades.js` 的 `kind:'art'` | |
| 形态变 | `p.pendingStyleShift` | **新机制，需在 drawSprite 里消费** |
| 存档 | `xx_gear_v100` | 遵循现有 `xx_<名字>_v0XX` 约定 |

**唯一需要动核心战斗逻辑的是吸血/自愈** —— 在 `enemies.js` 的伤害结算里加两行。其余全是纯数据。

## 十一、明确不要做

| 系统 | 原因 |
|---|---|
| 6+ 个装备槽 | 会变成排列组合题 |
| 每件都开宝石槽 | 数值翻倍 |
| 装备耐久 | 修仙题材 + 每日重复玩法，耐久只会让人烦躁 |
| 装备强化失败/降级 | 会把玩家气走 |
| 套装系统 | 4 槽最多 6 种组合，加套装等于再加一层组合题 |
| 大规模装备池 | 现有 8 件传说 + 9 件普通起步就够 |

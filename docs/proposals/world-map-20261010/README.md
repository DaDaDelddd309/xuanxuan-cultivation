## 2. 五层设计要点

### 2.1 区域 Region — 让规则挂在地上,而不是挂在点上

一个区域 = 一片有统一规则的地盘。节点是坐标,区域是规则。

关键设计:**危险度、产出、昼夜影响、势力、封锁全挂在区域上**。
新增 50 个节点不需要为每个重填一遍规则。

```js
{ id:'r_heifeng', name:'黑风山道', danger:2, faction:'f_heifeng',
  nodes:['n5','n7'],
  dayNight:{ nightDangerMul:1.6, closedTypes:['outpost'] },
  sect:null }
```

昼夜倍率刻意与 `items.js:194` 的 `DAY.bonus()`(1.35)同源 ——
地图和背包必须用同一套昼夜经济学,否则玩家会算出「夜里的地图」和「夜里的收益」互相矛盾。

### 2.2 节点 Node — 5 + 5 + facet

**不把 10 个愿景词都做成 type。**

| 类别 | 例子 | 为什么 |
|---|---|---|
| **行为不同 → type** | field / elite / secret / boss / rift / mine / outpost / wonder / gate | 决定「进不进回合制、能不能打、能不能占领」 |
| **只是身份 → facet** | town / sect / guild / port / harvest / cursed / contested | 只决定「进去之后挂什么菜单」 |

把身份塞进 type 的代价:15 种 type × 每种 8 个行为分支 = 没人敢改的分支地狱。
对照现实:`ui.js:546` 现在**5 种 type 就已经要分三段** `if(field)` / `if(elite|secret|boss)` / else。
翻三倍就是灾难。

facet 让「落云镇 = village + town + guild」成为可能,而 type 数量不变。

### 2.3 路网 — 从「坐标推导」改成「数据」

现状 `buildEdges()` 从曼哈顿距离算边。改不动的原因是它**表达不了差异**:
n5-n8 是官道还是野路?坐标算不出来。

改造后 22 条路(15 legacy + 7 new)全部显式声明 `kind` / `dist` / `enc`。

**寻路从 BFS 换成 Dijkstra**。为什么必须换:小图上两者结果常常一样,
但一旦有了 `dist`(官道 20 里 vs 秘径 6 里),「跳数最少」就完全错了 ——
系统会让玩家走 5 段野路去 100 里外,而官道只要 2 段 60 里。

实测(阶段 2 开启后):

```
n0->n1   ticks= 2  dist= 12里  pEnc=0.05
n0->n9   ticks= 6  dist= 26里  pEnc=0.22
n0->n8   ticks=12  dist= 66里  pEnc=0.70   ← 深入险地,七成会出事
```

封锁验证:`r_n5__n8` 被封后,`n0→n8` 自动改走 `r_n4__n7 → r_n7__n8`。

### 2.4 搜打撤 — 三个命脉 + 一个不能犯的错

三条命脉,缺一条系统就不成立:
1. **有限时间** `extractBy`
2. **有限容量** `stash.cap = 30`
3. **会失去东西** 死了 secured 全没

三类携带物:

| 类别 | 带出去 | 失败撤离 | 死亡 |
|---|---|---|---|
| `secured` | 赚 | **全没** | **全没** |
| `insured` | 赚 | **全没** | 赔 60%(出发时先交 8% 保费) |
| `keep` | 不算 | 保住 | 保住 |

**唯一不能犯的错:把 `extract_fail` 和 `death` 合并。**
失败撤离 = 东西丢了人活着,还能再来;死亡 = 人没了额外掉。
合并之后,玩家的最优解变成**永不撤离、死在半路** —— 搜打撤当场死亡。

代码里用显式迁移表 `TRANSITIONS` 挡住:
```js
export const TRANSITIONS = {
  prepare:['deployed'], deployed:['prepare','in_run'],
  in_run:['extract_success','extract_fail','death'],
  extract_success:[], extract_fail:[], death:[],      // 终态
};
```

`keep` 的存在不是仁慈,是**防滚雪球归零**:连输三把就重开,玩家会删档。

### 3.1 阶段 0 的完整性保障

阶段 0 加进来是「死代码」,但它不是无用功 —— 它带着三个**可执行的断言**:

```js
verifyLegacyIntact()   // n0-n10 一个不少、一个不变、x/y 都在
verifyRegionCoverage() // 11 个 legacy 节点全部归入区域
verifyNetwork()        // 路网自洽 + n8/n4/n5 在无封锁下可达
```

这三条已在本仓库实测通过:

```
legacy intact = {"ok":true,"problems":[]}
coverage      = {"ok":true,"orphanNodes":[],"orphanDens":[]}
net(core)     = {"ok":true,"errors":[],"unreachable":[],"lockedStory":[]}
net(all)      = {"ok":true,"errors":[],"unreachable":[],"lockedStory":[]}
```

`verifyNetwork` 里的 `lockedStory` 是个**剧情护栏**:
它专门检查 n8 / n4 / n5 是否可达。这三个节点挂着 5 条叙事线里的绝大部分 ——
**一旦某次改路把它们堵死,这个断言立刻挂掉**,而不是等到玩家发现主线断了。

- 新节点 —— 一律 `n11` 起,**永不复用、永不重排**。
- 区域 id 用 `r_` 前缀 —— **绝不与节点 id 混用**。

### 4.3 该不该做 —— 明确的「不要做」清单

这些**看着像愿景的一部分,实际是陷阱**:

| 不做 | 理由 |
|---|---|
| **副本/幻境的楼层脚本系统** | `duel.js` 已经是「特殊遭遇」了。再搞一层实例化状态机 = 两个回合制系统 |
| **领地攻防 / 攻城** | 需要 NPC 势力 AI、外交、围城规则。这是另一个游戏 |
| **真实商会经济(供需模拟)** | `market.js` + `merchant.js` 已经覆盖「买到卖出去」。真供需 = 平衡灾难 |
| **实时地图行走(点哪走哪)** | 本作是回合制/肉鸽。实时赶路是**另一个品类**,UI 工作量翻倍且与肉鸽手感冲突 |
| **程序化生成的无限世界** | 30 个节点以内,手工编排 > 程序生成。程序化会让剧情无处安放 |
| **装备耐久系统** | `extraction.js` 的 `__mate__` 钩子留着就行。耐久是独立的一大坨 |
| **节点级背包** | `Stash` 已经覆盖。仓库容量上限就是全部 |
| **声望/阵营好感度** | `relations.js` 已有宿敌(Nemesis)与称号(Titles),别开第三套 |
| **多���世界 / 地下城层** | 不在愿景里,且会彻底改变地图数据结构 |

### 4.4 最小可行版本:**只做 20%**

**做阶段 0 + 阶段 1 + 阶段 2,砍掉 3/4/5。≈ 700 行。**

**得到什么:**

1. 地图从「11 个点的网格」变成「5 片有名有姓的地方」——
   河谷 / 商道 / 秘境 / 山道 / 遗墟,每片有归属势力、危险等级、昼夜影响。
2. 赶路有距离、有耗时、有选择。站 n0 看 n8,系统告诉你:
   「66 里,12 次行动,七成会出事,途经 5 段路」——
   **而不是像现在这样,点一下就过去了。**
3. 路线受封时自动绕道(阶段 3 再开放封锁)。

**得不到什么:** 搜打撤、遭遇、新节点。

**但这是对的。** 因为:
- 区域 + 路网是**后续一切的公共底座**(搜打撤要区域、新节点要区域、封锁要路网)。
- 它**零机制风险** —— 不改 `endRun` 的结算链,不动 26 个存档键,不改 main.js 签名。
- 它是**玩家最容易感知的价值** —— 「哦,这是一个世界」,而不是「哦,数值变了」。

**搜打撤(阶段 4)是最高风险项,应该放到最后,而且要独立成一个版本。**

## 6. 落地时最先要做的 3 件事

1. **把 `FEATURE_FLAGS` 接进 `index.js` 的装配**,并让 `index.js:99 init()` 调用 `World.init()`。
   全 false 的状态下,这次提交对玩家的影响是**零** —— 这是安全的第一次提交。

2. **搬三个 `verify*` 到 `tests/`**。它们现在是开发期护栏,
   上了 CI 就是永久护栏 —— 尤其是 `lockedStory`(剧情可达性)。

3. **先只做阶段 1**(区域着色)。它改的全是渲染,不改任何状态、不改任何存档键。
   拿它验证渲染管线走通,再动阶段 2 的逻辑。

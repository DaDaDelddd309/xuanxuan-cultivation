## 二、需要更正的一条断言（不是 bug，但会误导施工）

**聊天汇报里说：`world.js:57` 的 `grid: 6` 是错的，
「这就是地图只占顶部 1/3 的根因，V0.95 只修了渲染层没修数据层」，
所以「把 grid: 6 改成 4，一行，让 lint 转绿，也顺手解决地图占不满的问题」。**

**后半句不成立。** 实测：

1. `WORLD.grid` 在产品代码里**零消费者**。精确搜 `WORLD.grid` 全项目只有一处命中，
   而且是 `ui.js:873` 的**注释**：

   ```js
   // V0.95:原来按 WORLD.grid(=6)算,但节点实际只用到 3 行 ——
   // 地图只占顶部三分之一,下面大片空白。按数据的真实范围算。
   const xs = WORLD.nodes.map(n=>n.x), ys = WORLD.nodes.map(n=>n.y);
   const x0=Math.min(...xs), x1=Math.max(...xs), ...
   ```

   `vMap()` **根本不读 `WORLD.grid`**，它按数据真实范围算。V0.95 已经修好了。

2. 所以改 `grid: 6 → 4` 是**零功能效果**的一行 —— 地图占不满这个现象早已不存在。

**要区分两件事**：
- 「`WORLD.grid` 是死字段」—— **对**，应该删。
- 「`grid: 6` 导致地图占不满」—— **错**，那是 V0.95 之前的事，已经修完。

README §3.3 的表述是准确的（*「删字段。`ui.js:807-813` 早已绕开」*），
**只有聊天汇报里那句因果推断是松的**。建议施工时以 README 为准，别按聊天里那句去改。

> 小出入：README 说绕开的位置是 `ui.js:807-813`，实际在 `873-877`。行号漂了，不影响结论。

## 四、同意的部分（评审意见）

**§4.4「只做 20%」是对的，而且这是整份材料里最有价值的一条判断。**

理由不是「省事」，而是它同时满足本项目的两条硬规矩：

- **零机制风险**：阶段 0/1/2 不碰 `endRun` 结算链、不动 26 个存档键、不改 `main.js` 签名。
  这和 AGENTS.md「改任何东西之前先跑基线」「逐个独立可验收」是同一条要求。
- **零存档迁移**：静态数据永不进存档，所以扩地图不需要迁移任何存档。
  这正是 XX-AUDIT-006 批 2 踩过的坑（存档键一改就是玩家进度归零），这里避开了。

**§2.3 坚持把寻路从 BFS 换成 Dijkstra，理由也对**：
小图上两者结果常常一样，但一旦有了 `dist`（官道 20 里 vs 秘径 6 里），
「跳数最少」就完全错了。这个陷阱很常见，值得留档。

**§2.2 type / facet 的拆分**（行为差异进 type，身份差异进 facet）是对的。
`ui.js` 现在 5 种 type 就已经要分三段 `if`，再翻三倍就是分支地狱。

**§4.3「不要做」清单**同样有价值，尤其「实时地图行走是另一个品类」这条判断准确。

# 灵伴变异体系 · 规格

> owner 方向（2026-10-10）：
> **克苏鲁水墨封印态 → 游玩/喂食逐步解除封印 → 形态随机分支**
> - 封印态用克苏鲁的**视觉语言**（漩涡、触手、不规则肢体）但保持**唯美不恐怖**
> - 变异方向**不由玩家直接选**，而是**像赌博一样按掉落物品的稀有度随机决定**
>   —— 普通稀有度大概率是「骷髅 / 克苏鲁」类，不会直接给你恶魔/巨乳/萝莉
> - 前期喂材料**决定先变哪儿**（肤色？还是肢体？），这是玩家唯一的手动权
> - 剧情决定「有没有眼睛 / 几只眼」这种根本性特征
> - 立绘**背景随阶段进化**
> - 每个细节都要**量化**，像建模一样一个参数一个参数

## 一、五阶段进化（每阶段一次立绘换装）

| 阶段 | key | 解锁条件 | 立绘状态 |
|---|---|---|---|
| **封印** | `sealed` | 开局默认 | 五官模糊、轮廓被墨缠绕、漩涡纹理、看不清脸 |
| **初醒** | `awaken` | 累计 1 次投喂 | 五官轮廓浮现，仍有墨痕覆盖，瞳色隐约 |
| **显形** | `reveal` | 累计 3 次 + 阶段材料达标 | 脸完全清晰，出现**第一个特征**（耳型 / 肤质） |
| **化形** | `morph` | 累计 6 次 + 第二次特征成型 | 两个特征成型，出现肢体变化，背景开始专属化 |
| **真身** | `true` | 累计 10 次 + 最终抉择 | 全部特征定格，背景完全专属，剧情揭示 |

**关键**：玩家能看到进度条（`n/10`），所以每次投喂都有即时反馈——
这是「变异」好玩的核心，不是等���了十次才看到东西。

## 二、变异方向 · 稀有度随机（赌博机制）

### 2.1 稀有度 → 变异族

| 投喂品阶 | 变异族 | 概率倾向 | 说明 |
|---|---|---|---|
| 清 / 淡（低阶） | **骸族** | ~70% | 骷髅、苍白、关节外露、克苏鲁骨骼感 |
| 清 / 淡 | **畸族** | ~25% | 不对称、多肢、比例失调（**唯美不恐怖**） |
| 清 / 淡 | **魅族** | ~5% | 极少出现 —— 低阶不该直接给「可爱向」 |
| 重 | **魅族** | ~40% | 脸开始偏向柔美 |
| 重 | **骸族 / 畸族** | ~60% | 仍偏向非人 |
| 浓 / 焦 | **魔族** | ~50% | 恶魔特征：角、翼、竖瞳、暗红皮肤 |
| 浓 / 焦 | **妖族** | ~30% | 福瑞特征：兽耳、尾巴、非人瞳（**兽耳不是人耳**） |
| 浓 / 焦 | **仙族** | ~20% | 纯欲向：人类特征但极度精致 |
| 太虚（传说） | **完全随机** | 100% | 唯一能强制转向的品阶 |

> ⚠️ 这就是你说的「赌博」：**低阶喂出来大概率是骸族**，不是你想要的恶魔/巨乳/萝莉。
> 想要可爱向，得攒到「重」阶以上，还得看脸。**这就是抽卡的乐趣与痛苦。**

### 2.2 概率公式（沿用 loot.js 原则）

```js
// 不用绝对概率硬编码，用「品阶权重 × 族倾向」相乘后归一化
const FAMILY_TABLE = {
  1: { bone: 0.70, aberrant: 0.25, allure: 0.05 },   // 清
  2: { bone: 0.62, aberrant: 0.33, allure: 0.05 },   // 淡
  3: { bone: 0.30, aberrant: 0.30, allure: 0.40 },   // 重
  4: { demon: 0.50, beast: 0.30, celest: 0.20 },     // 浓
  5: { demon: 0.45, beast: 0.30, celest: 0.25 },     // 焦
  6: { bone:.2, aberrant:.2, allure:.2, demon:.15, beast:.15, celest:.10 }, // 太虚
};
```

**保底机制**（必须有，否则玩家会弃坑）：
- 连续 10 次未出「非骸族」→ 第 11 次强制在 `{allure, demon, beast, celest}` 里抽
- 这条要写进代码注释，不是可选优化

## 三、玩家唯一的手动权：先变哪儿

每次投喂前，玩家**选一个「改造部位」**（这是设计上的关键决策点）：

| 部位 | 说明 | 影响 |
|---|---|---|
| **肤色 / 肤质** | 最基础 | 从纸白 → 苍白 → 灰蓝 → 暗红 |
| **肢体** | 手脚、关节、翼 | 从正常 → 修长 → 非人比例 → 多肢/翼 |
| **眼** | 眼睛数量与形态 | 见 §四 |
| **耳** | 耳型 | 见 §四 |
| **尾 / 角** | 追加器官 | 0 → 1 → 2 |

**规则**：
- 部位可以**重复选**（专精某处）—— 喂得多 + 喂得专 = 该部位变化显著
- 每次投喂 = 「随机决定变异族」+「玩家决定改造部位」，**两个正交**
- 这就是你要的：「前期喂材料就定义好目前先改肤色还是肢体变化」

## 四、每个部位的可量化参数表（像建模一样）

### 4.1 耳（你说的「精灵上扬 / 哥布林下垂 / 人类变小 / 恶魔尖」）

| 族 | 参数 | 量化 |
|---|---|---|
| 人类（初始） | `earType: 'human'` | 长 1.0，角度 0°，贴头皮 |
| 精灵 | `'elf-up'` | 尖端上翘 **35°**，长 1.35，贴面少 |
| 兽（福瑞） | `'beast'` | 三角立耳，外翻 20°，长 1.15，**内侧绒毛** |
| 恶魔 | `'demon'` | 尖角，长 1.8，**螺旋向后 22°**，硬质 |
| 哥布林 | `'goblin'` | 下垂 **40°**，长 1.5，宽 1.4 |
| 骸 | `'bone'` | 无耳廓，骨刺外露 |
| 畸 | `'asym-ear'` | 一耳正常一耳变异（左右不对称） |

### 4.2 眼（剧情决定「有没有眼睛 / 几只」）

| 族 | 参数 | 量化 |
|---|---|---|
| 初始 | `eyeCount: 2` | 人类眼型 |
| 骸 | `'hollow'` | 2 只，**眼窝内无眼珠，幽蓝微光** |
| 畸 | `'third-eye'` | **3 只**（额心 1 只，竖瞳） |
| 魔 | `'slit'` | 2 只，**竖瞳** |
| 妖 | `'beast'` | 2 只，**虹膜横裂** |
| 仙 | `'luminous'` | 2 只，**全瞳无瞳仁** |
| 极端 | `'many'` | 4~6 只，分布不对称（畸族专有） |

> **剧情锚点**：`eyeCount` 与「有没有眼睛」由**剧情节点**决定，不由随机决定。
> 这是你说的「剧情决定有没有眼睛」—— 随机给的是**形态**，剧情给的是**存在与否**。

### 4.3 肤色 / 肤质

| 参数 | 取值范围 | 说明 |
|---|---|---|
| `skinHue` | 0~360 | 纸白 35° → 苍白 30° → 灰蓝 210° → 暗红 355° |
| `skinSat` | 0~0.35 | 骸族低（苍白），魔族高（暗红） |
| `skinRough` | 0~1 | 0=光滑、0.5=鳞片初现、1=骨质感 |

### 4.4 肢体

| 参数 | 取值 | 说明 |
|---|---|---|
| `limbRatio` | 5.5~8.5 | 头身比，随解封逐步「成人化」 |
| `extraLimb` | 0 / 2 / 4 | 多肢（畸族） |
| `wingType` | none / membrane / feather / demon | 翼 |
| `jointVis` | 0~1 | 关节可见度（骸族高） |

### 4.5 尾 / 角

| 参数 | 取值 |
|---|---|
| `tailCount` | 0 / 1 / 2 |
| `tailType` | none / fluff / spade / bone-tail |
| `hornCount` | 0 / 2 |
| `hornSpiral` | 0~1（恶魔角螺旋度） |

| 阶段 | 背景 |

## 六、命名规则（配合广播条）

命名影响**念起来的感觉**，也影响玩家选材料：

- **封印期**：叫「宝宝」或玩家起的封印代号（**不显示真名**）
- **真身**：名字下方显示称号，如「骸·长夜」「魔·赤瞳」
- 广播条里：名字用 `--cc-name`（金），称号用更暗的小字
- **族徽标记**：名字前加符号 `☠`（骸）/ `♆`（魔）/ `✦`（妖）/ `❈`（仙）

## 九、参考（已联网核实，2026-10-10）

owner 提到的「以太风吹就会变异」的像素猎奇游戏，**已核实：那个游戏是《伊洛纳 / Elona》**。

### 9.1 核实过程与证据

| 检索 | 结果 |
|---|---|
| Steam 商店搜索 API `term=crona` | **零结果** |
| `term=krona` / `term=crona mutation pixel` | 零结果或全不相干 |
| Steam `term=crone` | 只有 Warhammer / Graveyard Keeper / Daughter of Crone 等无关条目 |
| itch.io `q=crona` | 空响应 |
| 搜「以太风 + 变异 + 游戏」 | **全部命中《伊洛纳》** |

**结论**：
1. 不存在名为「Crona / 克洛纳」的游戏。
2. 中文「克洛纳」与「伊洛纳」仅差首字，`Crona ↔ Elona` 是辅音偏移 —— owner 记的是**伊洛纳**。
3. 另有两处记忆偏差：**它不是像素游戏**（是 ASCII/字符画面 roguelike），
   「以太风吹就变异」也不是它的机制描述。

> 注：`web_search` 工具后端在本机不可用（`MATRIX_TOOL_REQUEST_FAILED`），
> `cn.bing.com` 对本机做了降级（查「克洛纳」返回字典释义），
> 最终用 **360 搜索 + Steam 官方 API** 完成核实。此结论可复现。

### 9.2 真正值得借鉴的一点

Elona 的价值不在它的表现形式，而在它的 **mutation（变异）系统**：
变异是**给角色挂随机特性**的机制，正负特性混着出现，玩家**没法直接点单**——
要素是「要吃低概率的好东西，也得接受坏的一起来」。

这与本规格的「稀有度随机 + 保底」同构，所以**借鉴它"接受坏搭配"的态度**即可，
不必照搬表现形式。本规格的变异逻辑是按 owner 描述**独立设计**的，
不是对 Elona 的复刻。

### 9.3 仍然成立的通用设计经验

- 变异应是**不可逆的、渐进的、可见的** —— 每次都让玩家看到变化
- 随机决定方向 + 玩家决定部位 = 「有掌控感又有惊喜」
- 必须有**保底**，否则抽卡体验会崩（已实现并有反向验证，见 §十）
- 每个参数都要**能量化**（角度/长度/数量/饱和度），否则出图无法稳定复现

### 10.1 已实现的关键约束

- **族每次投喂都重抽**，不是第一次抽完就锁死。最初写成 `mut.family || rollFamily(...)`，
  导致族在第 1 次后永不改变、保底计数涨到 10 以上却再也不会触发 `rollFamily`——
  整个稀有度轴形同虚设。由测试断言「族会随投喂变化」抓出。
- **`load()` 无条件重建 `mut`**，否则读老存档会把内存里上一局的变异进度带过来。
- **`skippedMorph` 不能写成 `feeds < STAGES[3].need`**：`canChooseFinal` 已要求 feeds ≥ 10，
  该条件恒为 false，字段成了永不触发的死数据。
- **`eyeCount` 与「有没有眼睛」只能由 `dramaGrant()` 授予**，族的默认眼型永远盖不过剧情。

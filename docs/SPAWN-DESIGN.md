# 刷怪导演 · 设计说明（V0.99 · XX-SPAWN-001~007）

> 这份是**为什么这么算**，不是 API 文档。调参请直接看 `js/game/director.js` 的 `P` 表。

---

## 0. 一句话

旧 spawner 只看时间，所以「后期爆炸」且跟玩家行为无关。
现在改成**追一个随玩家行为浮动的目标怪量**——负反馈，天然稳定。

---

## 1. 算法

```
desired(目标怪量) = [MIN_ALIVE + 压力 × (MAX_ALIVE − MIN_ALIVE)] × 两道闸门 × 呼吸(t)
rate  (生成速率) = clamp((desired − 实际) × GAIN, 0, RATE_MAX)
```

**为什么是控制器而不是定时器**：定时器只能「到点就刷」，玩家做多做少完全不影响。
控制器是「少了就补、多了就停」，场面自己会稳在一个带里。

### 参数

| 参数 | 值 | 依据 |
|---|---|---|
| `MIN_ALIVE` | 4 | 保底。owner:「不是挂机,是有保底刷怪,只是不再会一堆」 |
| `MAX_ALIVE` | 92 | 满压力时的目标带 |
| `cap` | 150 | 硬顶，任何模式都不越过 |
| `GAIN` | 0.75 | 收敛速度。太大→抖动，太小→补不上 |
| `RATE_MAX` | 7.5/s | 单秒补怪上限 |
| `popGatePow` | 1.6 | 库存闸门陡度 |
| `tierGateMax` | 0.55 | 档位闸门最多砍 55%（留 45% 保底） |
| `decaySlow` / `decayFast` | 0.022 / 0.075 | 正常 / 停手后（>6 秒） |
| `fuelCap` | 0.32 | 场上未捡宝石的存量燃料封顶 |

### 呼吸

`breathe(t) = 1 + 0.10·sin(t/7.3) + 0.06·sin(t/2.9+1.7)`

两个不可通约的周期叠加 ⇒ 连续但读不出周期。玩家感觉是「潮」，不是节拍器。

## 2. 压力从哪来（两条独立燃料）

| 来源 | 数值 | 兑现 |
|---|---|---|
| 捡宝石（蓝/绿/红） | +0.055 / 0.085 / 0.14 | 1 只起，34% +1，11% 再 +1 |
| 击杀怪 | +0.045 | 1 只起，42% +1，14% 再 +1 |

设计意图：**想变强就得主动去捡**。站着打也能维持场面（击杀在供压），
但涨不上去——要往上走，必须动起来。

档位是闭合的：高级怪掉高级宝石，高级宝石刷高级怪。

> **只有宝石是燃料。金币不喂压力。**
> 否则捡一次钱就凭空多出妖物，玩家很快能摸出规律，机制当场失效。

---

## 3. 「不被看穿」是设计目标

第一版我做了 `status()`，把内部阈值做成 UI 文案（「妖物正在散去」）。**这是错的**：
玩家能读出规则，就等于把变量表摊开了。

现在的纪律：
- 界面文案零解释（`test-director` [9] 有断言守着，只扫字符串字面量）
- 内部状态不挂 `window`（控制台能读）
- 玩家只会感觉到「我不动的时候怪少一些」

---

## 4. 护栏是一条可投入的成长线

owner 的意图是让玩家**有得选**，不是平衡问题：

```
护栏 = (WARD_BASE + (篝火等级−1) × WARD_PER_LV) × 昼夜倍率 × 坐骑倍率
护栏 ≥ 拾取半径 × 0.55   （护栏不能形同虚设）
护栏 ≤ 拾取半径 × 2.60   （也不能无限大到没取舍）
```

| 篝火等级 | 白天护栏 | 对 800 拾取 | 含义 |
|---|---|---|---|
| 1 | 130 | 440 | 追不上 → 外沿有代价 |
| 3 | 480 | 480 | 临界 |
| 5 | 830 | 830 | **能挂机** |

两条曲线独立可升：**拾取撑大、篝火没投 → 有代价；砸源石升篝火 → 安逸挂机。**

> 这个坑 owner 明确点过：「扩张拾取宝石范围的技能会让这个机制变成挂机神技」。
> 解法是**靠控制器兜住，不给技能加惩罚**——加惩罚会被玩家读出来。
> 狂捡 200 次，目标带依然 ≤ `MAX_ALIVE × 1.11`；场上超硬顶时 `rate = 0`。
> 狂捡的代价不是「被削弱」，而是**目标带一直顶在高位**：想安全就少捡，想强就得承受。

### 昼夜

`WARD_BY_PHASE`：白天 118 / 晨 152 / 黄昏 172 / **夜 218**。
`stepWard` 平滑跟随（每秒最多 24px），不是跳变。
于是「什么时候生火」成了真决策——夜里妖物最多，那时候火才是刚需。

## 5. 余烬（XX-SPAWN-007）

夜里人物身上缠灰烬火星，让玩家**只靠肉眼**知道现在是夜里第几段。

- 闪烁频率随夜段推进衰减（3.2Hz → 0.8Hz）：刚添柴最旺，快烧完最弱
- 后 22% 进入「将熄」态 → 闪三下 → 提示该续源石了
- 天亮余烬结束
- 粒子用黄金角散布（137.5°）——均匀不重叠，像随机飘的灰烬

**那是一个决策点，不是惩罚。**

---

## 6. 保留了纯时间驱动

owner:「纯时间驱动的可以再未来作为幻境,或者某些副本的机制,你别删掉啊」

```js
setSpawnMode('timed')   // 旧的纯时间间隔曲线
setSpawnMode('budget')  // 默认:行为驱动
```

给幻境 / 副本 / 限时挑战用——那些玩法里玩家就是要被节奏推着走，
不能因为站着不动就消停。

---

## 7. 架构

参考开源社区的 pressure-based director：**导演只产出旋钮，不直接决定生成。**

```
Director  →  desired / rate        （旋钮）
spawner   →  读旋钮，决定生成        （执行）
enemies   →  读 spawnOptsFor()      （强度）
```

强度曲线只有一份（`spawnOptsFor`），导演的「宝石兑现」也走它。
复制两份必然对不上，弱的那边先崩。

---

## 8. 参数怎么调

手感不对时按这个顺序试，别一次改一堆：

| 症状 | 改什么 |
|---|---|
| 还是太多 | `MAX_ALIVE` 往下，或 `GAIN` 降 |
| 站着不动还是被打死 | `decayFast` 降，或 `MIN_ALIVE` 降 |
| 捡宝石没感觉 | `fuel.*` 调高 |
| 场面太死板 | `breathe` 的两个系数调高 |
| 挂机太难 / 太容易 | `WARD_PER_LV` 降 / 升 |
| 后期还是爆 | `cap` 降，或 `tierGateMax` 调高 |

改完必跑 `npm run check`。
